Tech stack

Each layer has a clear boundary: the UI never writes the sheet from raw model text; the engine is authoritative; the file helper handles disk and provider proxy.

Frontend

React 19 + TypeScript + Vite 6

Single-page UI: custom grid (A–Z × 200), formula bar, worksheet chrome, chat sidebar, accept/reject preview, and toolbar with provider/model picker.

Engine

Workbook & formulas

In-browser workbook engine, operation checker, undo/redo. Built-in formulas include SUM, AVERAGE, COUNT, and IF.

AI

Structured proposals

Models return JSON operations (not free-form patches). Client repairs and validates schema; proposeEdits never mutates the live grid directly.

Server

Node file helper (:8787)

ExcelJS for .xlsx open/save, backups, /api/health and /api/ready, model settings, and proxy to Ollama (default), Gemini, or Groq.

Testing

Vitest

Unit tests for engine, shared types, server handlers, readiness, and curated sheet-friendly model lists.

Runtime

Local-first AI

Default provider is Ollama at 127.0.0.1:11434. Optional cloud keys live in gitignored server/model-settings.json.

Architecture & workflow

End-to-end path from a user prompt to a saved workbook. Preview runs against a copy; acceptance applies operations to the real sheet.

1
User prompt + selection context Chat sends workbook slice and instructions when readiness is green.
↓
2
Provider (Ollama / Gemini / Groq) File helper proxies the request; API keys stay on the server when configured.
↓
3
Structured JSON operations Schema + repairs in src/ai/; no direct sheet writes from model output.
↓
4
Engine checker on a copy Invalid ops are blocked; preview highlights proposed changes.
↓
5
Accept or reject Accept merges into the live workbook; reject discards the proposal. Undo available after accept.
↓
6
Save .xlsx ExcelJS export; chat history stored separately from the workbook file.

Layer boundaries

Layer Responsibility
Engine / checker Authoritative edit validation; new operation types need tests.
AI propose Schema and repairs; no direct sheet writes.
Server helper Files, settings, provider proxy, readiness gates.
UI When AI runs, how errors read, model curation (max three sheet-friendly models per provider).

How to use the app

Navigation mirrors the real UI: toolbar on top, grid on the left, AI chat on the right. Chat stays disabled until the readiness gate passes.

Layout at a glance

Toolbar

Open / save workbook, undo/redo, provider & model, readiness status pill, advanced settings.

Grid (left)

Cell editing, formula bar, range selection. Use Preview sample edit anytime — local checker only, no model call.

AI chat (right)

Natural-language requests. Send unlocks when file helper, sample edit, and /api/ready are all green.

  1. Start dev stack

    From the repo root, run npm run dev:all and open http://127.0.0.1:5173. Vite proxies /api to port 8787.

  2. Open or create a workbook

    Use toolbar actions to open an existing .xlsx or work in a new sheet. Files default to ./workbooks unless WORKBOOK_DIR is set.

  3. Wait for readiness

    Fix setup issues via the status strip if needed: health check, sample edit pass, provider/model and API key (for Gemini/Groq). Preventable failures never call the model or dump raw provider errors in chat.

  4. Prompt with context

    Select cells when relevant, then ask for tables, formatting, or formulas — e.g. “Create a monthly expense tracker with totals.”

  5. Review preview

    Inspect proposed operations on the preview copy. Accept applies to the live sheet; Reject drops the batch.

  6. Save

    Save through the file helper; reopen in this app or Excel. Backups run before overwrite when configured.
